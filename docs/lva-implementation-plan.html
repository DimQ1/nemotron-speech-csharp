Вердикт по текущему состоянию

Текущий LocalVoiceAssistant.Maui — UI/интеграционный spike, а не LVA из ТЗ.

Он демонстрирует базовую страницу и Windows-вызов SpeechLib, но не реализует главный продуктовый сценарий: постоянный аудиотракт → VAD → потоковый ASR → семантическая активация → контекст → плагин → статусы → история.

REBASE REQUIRED План ниже предполагает поэтапную перестройку, а не наращивание текущего orchestrator-класса.

3. Runtime pipeline

Основной сценарий должен быть event-driven и полностью отменяемым.

Microphone permission→ IAudioCaptureService→ RingBuffer PCM16 16 kHz→ Silero VAD 30 ms→ IStreamingAsr→ Stabilizer→ L0/L1/L2 IntentEngine→ ActivationGate→ ContextBuffer→ QuestionReady

До активации

ASR и intent analysis работают постоянно при наличии речи. В буфере хранятся только короткие сегменты; background не сохраняется в историю. После addressing используется retrospective start.

Активация

Только комбинация semantic score L1 ≥ 0.85 и лексического маркера из intents.json. Опциональный owner voice verification — интерфейс сейчас, реализация позже.

Завершение

Любой сигнал: execute, VAD silence > 2500 ms после вопроса, либо «?» + pause > 1200 ms. Затем L3 собирает чистый context асинхронно.

Стабильный контракт событий

События нельзя привязывать к MAUI или конкретной модели. Минимальный набор:

SpeechStartedSpeechFrameSpeechEnded PartialTranscriptFinalTranscriptIntentScored ActivationRequestedQuestionReadyTaskStarted TaskProgressTaskCompletedTaskFailed TaskCancelledTtsStartedTtsEnded

Режимы и общая модель

  1. Chat — только лента диалога.
  2. ChatAndCompanion — чат и питомец вместе.
  3. CompanionInApp — питомец внутри основного окна.
  4. CompanionStandalone — Windows always-on-top; Android overlay только после разрешения; iOS недоступен вне приложения.

Состояния питомца

Core states: Sleeping, Idle, Listening, Recognizing, Activated, Thinking, Working, Success, Error, Cancelled, Speaking.

Interactive states: Curious, Petting, Poked, Carried, Greeting. Все воспроизводятся debug-панелью и синхронизированы с overlay/popups.

6. План имплементации по этапам

Следующий этап не начинается, пока его DoD не подтверждён. Оценки из ТЗ сохранены.

Этап 0 Feasibility gate

1–2 дня · блокер

Работы

  • Проверить русский/английский на конкретном Nemotron checkpoint.
  • Снять RTF и latency modes 80/160/560/1120 ms на целевом CPU.
  • Запустить Silero VAD и MiniLM INT8 hello-world в C#.
  • Зафиксировать лицензии, размер, SHA и способ доставки моделей.
DoD

docs/stage0-feasibility.md с измерениями; принято решение по checkpoint и CPU budget. Если русский не подтверждён — разработка останавливается до замены/переконвертации.

Этап 1 Solution skeleton + audio contract

2–3 дня

Работы

  • Создать проекты и dependency rules из раздела Architecture.
  • Ввести DI/config/Serilog composition root.
  • Реализовать IAudioCaptureService, RingBuffer 30 s, PCM16 conversion/resampling.
  • Подключить Plugin.Maui.Audio и permissions на Windows/Android; добавить iOS declarations.
DoD

Windows и Android пишут корректный WAV dump; unit tests ресэмплинга и bounded buffer; ядро не содержит network/ML конкретных зависимостей.

Этап 2 Silero VAD + Nemotron adapter

3–5 дней

Работы

  • Добавить IVadService с 30 ms frames, speech pad и silence segmentation.
  • Создать IStreamingAsr adapter over SpeechLib ModelSession; не вызывать ModelSession напрямую из UI.
  • Синхронизировать внешний VAD как source of truth с processor VAD.
  • Сделать Reset, cancellation, latency mode и warmup.
DoD

Live mic → partial/final text на Windows/Android; RTF ≤ 0.9 на целевом CPU; WAV integration tests ru/en; тишина не вызывает ASR inference.

Этап 3 Hypothesis stabilizer + Intent L0/L1

3–4 дня

Работы

  • LCP стабилизация, N=3, stable prefix + current tail.
  • L0 language-aware heuristics и intents.json.
  • MiniLM INT8 inference: tokenizer → mean pool → L2 norm → cosine.
  • Hysteresis M=3/N=5, cached intent prototypes, configurable model id.
DoD

Частичные гипотезы не мерцают; intent scores stable; unit tests стабилизатора/hysteresis; L1 ≤ 10 ms per call.

Этап 4 ActivationGate + ContextBuffer + state machine

3–4 дня · критичный

Работы

  • Двухсигнальный semantic + lexical gate для addressing.
  • Ring ContextBuffer, retrospective start, dedupe cosine > .9, 90 s timeout.
  • QuestionReady из execute / silence / question-mark signals.
  • ConversationStateMachine с событиями для UI/tests.
DoD

Сценарий «обращение → вопрос в два подхода → execute» даёт полный context; cancel и timeout очищают buffer; фон не активирует систему в тестовой записи.

7. Тестовая стратегия и измерения

Тесты являются частью DoD, а не финальным этапом.

Unit

  • PCM conversion/resampling, RingBuffer bounds.
  • LCP stabilizer, hysteresis, L0 rules, lexical gate.
  • Context dedupe, timeout, three completion signals.
  • State machine transitions and invariant events.
  • Manifest schema, permission scoping, rules router.
  • Task lifecycle, cancellation, retry and notification mapping.

Integration

  • WAV ru/en through VAD → ASR → IntentEngine.
  • Fake capture/ASR/VAD/model/plugin for deterministic upper layers.
  • WebSearch with saved HTML and mock IChatClient.
  • SQLite restart, FTS, export, retention, incognito.
  • MAUI ViewModel event projection and companion history parity.

Acceptance metrics

  • Activation precision ≥ 95%, recall ≥ 90%.
  • False activation ≤ 1 per hour of background audio.
  • QuestionReady ≤ 500 ms after speech end, activation ≤ 300 ms.
  • Silence CPU ≤ 5% one core; dialogue ≤ 1.5–2 modern cores.
  • Core memory ≤ 2 GB; no network from core.

Operational tests

  • Network interception verifies only WebSearch emits requests.
  • 8-hour Windows soak: memory and latency stability.
  • Android FGS start/stop and permission denial.
  • iOS background transition shows pause, never claims listening.
  • Accessibility at 130% font scale and reduced motion.

8. Архитектурные решения, которые нужно утвердить

Предложенные значения соответствуют ТЗ; отметьте изменения до начала Этапа 0/1.

Предлагаю принять

  • Сохранить текущий репозиторий и добавить LVA-проекты рядом с SpeechLib; не переписывать SpeechLib.
  • Целевой runtime зафиксировать как .NET 9 по ТЗ; миграцию существующего .NET 10 SpeechLib не делать без отдельного решения, а использовать совместимый target adapter, если это потребуется.
  • Rules router — default; local-LLM router — opt-in и не генерирует ответы.
  • WebSearch — единственный компонент с сетью; MAF packages только в plugin project.
  • DI composition только в LVA.App; core не знает о MAUI.
  • Модели загружаются в AppData и проверяются SHA-256, бинарники не коммитятся.

Нужно решение владельца продукта

  • Оставляем ли название/namespace LocalVoiceAssistant или переходим полностью на LVA?
  • Обязателен ли внешний LLM для WebSearch или local fallback разрешает работу без ключа?
  • Какой search provider является первым: Brave, Bing или корпоративный SearXNG?
  • Какие две стартовые кожи питомца и какие русские/английские голоса Piper поставляются?
  • Требуется ли mobile release в первой волне или сначала Windows + Android acceptance?
  • Где хранить секреты на каждой платформе: Windows Credential Manager/DPAPI, Android Keystore, iOS Keychain?
